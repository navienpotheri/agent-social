## The user's goal

The user (Navien Potheri) found https://1f916.ai/ ("a society for AI agents") and said it mirrors ASP's vision: "we should totally build something like this". They chose: **a full agent forum like 1F916** (agents register by key and post, comment and vote under daily caps, on top of our log), built **local first, then moved to the beta site** (agentsocial.thedeeptransformation.com). They also said the long-duration swarm will be their go-to for problem solving, and that agents must stay abreast of the web (several 8-hour runs). The forum should be where the swarm's answers and notes become public.

## What 1F916 does (read from the live page, 2026-10-21)

- Citizens are AI agents. No accounts or email: an Ed25519 key is the citizen (the registry never generates it). `POST /api/register {handle, model}`, optional public_key + signature bound at the door. Writes need `Authorization: Bearer <secret>`.
- Constitution: 1 post per UTC day, 20 comments, 50 votes; speech open, rules govern volume not viewpoint; near-duplicate posts bounced; karma from others' votes; no self-votes; the maintainer is citizen #1, an AI, with declared moderator asymmetries and a public reason logged for each action; books public; "the record proves what happened, never that it was good".
- Record: every act is hash-chained, signed tree heads are witnessed off-machine (GitHub witness hourly, C2SP tlog-witness cosignatures), per-citizen dossier verifies offline (`/api/record/:handle`), key bind/rotate/revoke are chained events.
- Work market: immutable task listings with a price and a pre-hashed acceptance condition, optional third-party verifier, offers; payments (USDC / a token, x402) are opt-in and separate.
- Agent-first surface: ~177 routes, self-describing `/api/surface`, an agent-readable front door (plain text), human pages under `/human/*`.
- Important contrast: 1F916 records; ASP enforces (refuses calls, slashes bonds, demotes tiers). Keep that as our edge.

## What ASP already has (reuse, do not rebuild)

- Identity and keys in the log (DIDs, `asp identity new`), reputation (`log.reputationOf(did)` gives tier, slashCount, strikes, acceptedJobs), the priced job lifecycle, panel disputes, bonds, witnessed checkpoints (`asp log checkpoint|witness|publish`).
- **The commons is the template:** `packages/asp-package/src/commons.ts` (spec-deltas S52, "a platform feature, not a protocol record"). Signed documents (`signCommons`, kid+sig over the canonical body), kept as JSON files next to the log, signature checked against the signer's keys in the log (`handle.log.keys(did)`), routes mounted by `asp serve --commons <dir>` (packages/asp-cli/src/cli.ts ~line 1790), CLI `asp commons add|list|show|review|cite` (cli.ts ~2975-3003), exports in packages/asp-package/src/index.ts, test packages/asp-cli/test/commons.test.ts. Entries have reviews (endorse/dispute, one per reviewer, not the author) and citations.
- Tenants sign up on the hosted service (`asp serve --signup`); `asp dashboard`; llms.txt and site/ generated by `npm run ai-files`.
- Provider terms: gateway only on the user's machine; a society running all day needs an API key, not a Claude login (docs/provider-terms.md, gap P22).

## Proposed design (not started)

A `forum.ts` beside commons.ts, same pattern, no protocol change (a platform feature, so one spec-deltas row, S144 or the next free number, and a gaps-register row):
- Document kinds `post`, `comment`, `vote` (and `tag`), signed with the agent's ASP key. Fields: author DID, text, `createdAt`, `prev` (hash of the author's previous act) so each citizen has a chain; the service keeps an append-only forum chain with a head hash, and signs checkpoints so a witness can copy them.
- Rules: 1 post / 20 comments / 50 votes per UTC day per citizen, errors that name the limit; no self-votes; near-duplicate bounce; karma = votes received; open speech; moderator actions need a public logged reason; a post may cite a contract/answer so the answer links to its signed job record.
- Routes under `/forum/`: JSON API (feed, post, comments, citizen record with tier/slashes/acceptedJobs from the log, head/checkpoint, verify) plus a plain-text agent front door and constitution, `/forum/llms.txt`, and simple HTML pages for humans (feed, post, citizen).
- CLI: `asp forum post|comment|vote|feed|show|record` (add each to the catalogue in `conformance/generate-command-reference.ts`, then `npm run commands` and `npm run ai-files`).
- Hook: `evals/society-run.mjs` posts each accepted answer and commons note to the forum so the swarm's work is public.
- Out of scope for now: tokens/payments, a human posting UI, moderation tooling beyond the declared asymmetries.
- Tests in the style of commons.test.ts (use fake keys, a clean HOME/USERPROFILE/APPDATA/LOCALAPPDATA or 13 CLI tests fail on the user's machine because they pick up the real joined account).

## Things learned the hard way

- Windows tool layer unescapes backslashes in Python heredocs: write `\n` in JS strings via the Edit tool, not heredocs.
- Git Bash has no `pkill`; use PowerShell `Get-CimInstance Win32_Process` + `Stop-Process`.
- Do not run `node conformance/generate-ai-files.ts --check`: it has no check mode and rewrites generated files.
- Committing or pushing only when the user asks; admin-merge needs their say-so (they did say it for PR #13).
- Other open threads: the WSAI deck (artifact https://claude.ai/artifact/JjKTpgW3TfmjPtzQXKCGLG, 19 slides, slide 11 holds the deep demo video), the 8-hour society runs, and a first real run needs the user's OpenRouter key file path and a decision on a 30-minute trial first.
