# ASP v0.2: what the spec needs from the build

11 additions to write into the spec as built, and 5 decisions — now resolved (2026-09-27). Numbers in brackets are the items' numbers in the earlier 40-item list.

The rest of what the build had to settle is in [implementation-notes.md](implementation-notes.md), with no decision needed. Unbuilt work is in [backlog.md](backlog.md), and single-player mocks are in [../MOCKS.md](../MOCKS.md).

## Decided (2026-09-27)

| # | Topic | Decision | What changed |
|---|---|---|---|
| D1 | Learning data [32] | Metadata only, for now. No transcript content, diffs, or test output leaves the machine — only session counts, models, timestamps, tool-call counts. Revisit once the learning layer actually needs richer signals. | No code change; this is what's already built. |
| D2 | Probation after a runtime move [35] | Keep 7 days. Once a self-modification pathway exists, probation should force `self_modification` to `principal_approves` regardless of tier; nothing else is restricted. Who writes the canary suite stays open (Academy, Stage 2). | The registry now tracks each DID's current probation window (`EventLog.probation(did)`), derived from lineage `update` records carrying `probation_until`. Enforcement itself waits on a self-modification pathway, which doesn't exist yet (`docs/backlog.md`). |
| D3 | Identity bootstrap [20] | Keep trust-on-first-use for now. Must change before any hosted, multi-tenant network (already flagged in `docs/backlog.md`). | No code change. |
| D4 | Job diagram [13–16] | Adopt all three edges the build already added — two-step acceptance, one redelivery, revocation before delivery — into the spec's own diagram. They already match the spec's prose; only the diagram was narrower. | Spec-doc change (outside this repo); noted here for the record. |
| D5 | Log anchoring [21] | The log owner's own key periodically signs a checkpoint of the log's head; not published anywhere yet. | New: `asp log checkpoint --as <did>` signs `{seq, log_hash, signed_at}` and appends it to `~/.asp/checkpoints.ndjson`. `asp log verify` re-checks every stored checkpoint by independently replaying the log up to that seq (`EventLog.verifyCheckpoint`), not by trusting the stored value. |

## Write into the spec as built

| # | Spec section | Addition |
|---|---|---|
| S1 | Core objects: envelope [1, 2, 4] | Add `issued_at` and optional `cosigs`. `sig` is `{alg, kid, value}`. `id` = sha256 of the RFC 8785 canonical form of every field except id and signatures. Type strings look like `asp.mandate/v0.2`. |
| S2 | Core objects: numbers [3] | Signed records carry integers only; fractions are in permille. |
| S3 | Registry: identity [6] | v0.1 uses did:web for anyone who brings their own domain, and did:key (self-certifying, no domain) for anyone who doesn't; did:asp comes later without a breaking change. Added 2026-09-27, alongside the D1-D5 decisions, after the strategy review flagged that did:web-only identity ties "take your agent and leave" to whoever hosts the domain. |
| S4 | Core objects: record types [8, 9] | Passport, lineage edge, agent package, fleet and node become signed record types (17 in all, with Juror — see S12). Rebirth has none, by definition. |
| S5 | Bank: escrow [10] | The escrow lock travels inside the Bond record, since each transition emits one object. |
| S6 | Coordination: Contract [11] | The principal issues it, the performer co-signs it, and it is the first record of the job's chain. Intent/Offer (or Call/Proposal) are referenced, not chained. |
| S7 | Mandate [12] | Enumerate `self_modification`, `checkpoints` and `irreversible.policy`, and a dotted scope grammar such as `repo.read` and `pr.open`. |
| S8 | Registry: fleets [23] | A Fleet record is issued by its org. An agent joins by naming the fleet on its passport; it must share the fleet's sponsor, and the fleet must have room. |
| S9 | Registry: nodes [5, 24, 25] | A Node record delegates a short-lived key: it signs only as that node, never identity records, and expires. Under a Mandate, live nodes count against `max_parallel`. The person stays liable. A second Node record chained onto the first is an update — a rotation, or (setting `expires` at or before `issued_at`) an immediate revocation. |
| S10 | Transport: agent package [28, 29, 31] | Package layout, a manifest signed by the agent, and secrets as named placeholders that are never stored. May be a directory or a single gzipped tar file. |
| S11 | Learning: gates [35] | Memory changes and runtime moves are recorded as lineage `update` edges (layers `memory` and `backend`), written back after each successful run. A move's `probation_until` is tracked per DID in the registry. |
| S12 | Courts: juror stake (new, 2026-09-28) | A 17th record type, Juror (`spec/schemas/juror.schema.json`): self-issued, `{did, stake}`, chained per DID like Fleet/Passport — a later record updates the stake, locking more or returning some/all via the same credit ledger Bond/Settlement use. A ruling Attestation must be cosigned by a majority of the panel `drawPanel` draws (conflict-free: excludes the contract's principal, performer, and anyone they sponsor; seeded from the rejection that opened the dispute, so it's deterministic and replayable) — unless zero eligible jurors are registered anywhere, in which case any neutral DID may still rule, unchanged from the original mocked behavior (MOCKS.md #4). Chosen over a ledger-only (unsigned) stake specifically so staking is itself a real, verifiable, replayable commitment. |
| S13 | Bank/Registry: reputation as a slash consequence (new, 2026-09-28) | Deterrence, not a new record type: a DID's `tier`/`slash_count` (`EventLog.reputationOf`) is derived entirely from Settlement, never independently signed — same trust boundary as probation. A slash (`bond_slashed > 0`) demotes the backer's tier by one (floor 0) and counts it. `projectBond` then enforces two consequences on that same DID's *next* Bond: tier 0 is excluded from bonding outright (`tier_excluded`); below that, its own and its live fleet-mates' slash counts raise the minimum bond it must post for the contract's price (`bond_below_risk_floor` — 250‰ per own slash, 100‰ per fleet-mate's, capped at 1000‰). Agent-only: humans/orgs backing a job aren't tier-tracked. The 250‰/100‰ step sizes are a judgment call (like probation's 7 days), not a derived formula. |
| S14 | Courts: a ruling's fault is the settlement formula (new, 2026-09-28) | A ruling-backed Settlement (`basis: "ruling"`) can no longer declare arbitrary amounts: `projectSettlement` derives `escrow_released = floor(escrowLocked × (1000 − performerFault) / 1000)` and `bond_slashed = ceil(bondLocked × performerFault / 1000)` from the cited ruling's `fault` map, and rejects a Settlement that doesn't match (`settlement_mismatches_ruling`) — closing the gap where a bank could rule one way and settle another. `asp market settle` derives the same numbers automatically when the caller omits `--escrow-released`/`--bond-slashed`. Only applies when `basis: "ruling"`; `accepted` and `revoked` settlements are unaffected. |
| S15 | Learning: a slash shapes the agent's own next run (new, 2026-09-28) | No schema change — reuses the existing lineage `update` edge exactly as speced. `asp market settle` self-signs one for the slashed backer the moment `bond_slashed > 0` (only when that DID's own key is available locally; the log itself never signs on anyone's behalf). `asp pack` renders any such edges into `memory/PENALTIES.md`, which every runtime adapter's `materialize()` already copies into place with the rest of the package's memory — so the deterrent is literally in the agent's context at its next run, not just an entry in its signed history nobody reads. |
| S16 | Deterrence: tier 0 gates Mandate and Proposal too (new, 2026-09-28) | Extends S13's tier-0 exclusion past Bond: `EventLog.checkMandateTier` refuses a Mandate whose performer is at tier 0; `checkProposerTier` refuses a Proposal from a tier-0 issuer in allocation mode. Also: `asp orchestrate` now chains an immediate revocation onto a node's own grant the moment its task is known to have failed, instead of leaving the key live until its natural (up to 24h) expiry — the same chain-a-revocation pattern already used for manual node revocation. |
| S17 | Job lifecycle: principal-mode silence counts as acceptance (new, 2026-09-28) | A real lifecycle change, mirrored in both SDKs and covered by two new shared conformance vectors — unlike S12–S16, which were asp-log-only extensions on top of the lifecycle, not changes to it. `Contract` gets an optional `review_deadline` (mirrored from the cited Intent's `verification.review_deadline`, present only in principal-mode verification). `Settlement.basis` gets a fourth value, `"silence"`. A new lifecycle transition (`Delivered → Settled`, issuer `bank`, guard `past_review_deadline`: the settlement's own `issued_at` must be after the Contract's `review_deadline`) lets the bank close the job without ever citing an Acceptance Attestation — the principal's silence itself is never a signed record; what's signed is the bank's own settlement, timestamped after the deadline it's checked against. Vectors: `silence_after_deadline` (Settled), `settle_before_deadline` (`GUARD_FAILED`/`past_review_deadline` when settled too early). CLI: `asp market intent --review-deadline <iso>`, `asp market settle --basis silence`. |
| S18 | Subcontract nesting and Settlement fees (decided 2026-09-28) | Two of the four "needs a decision" items from that day, both decided as asp-log-only extensions (no lifecycle change, unlike S17). **Subcontract nesting**: an agent may hold the principal role on a Contract whose `parent_contract` names another — funded from its own balance, no automatic netting to the parent's escrow. `EventLog.checkSubcontract` requires the parent to exist, actually be a Contract, not already be Settled, and its `performer` to equal the child's `principal`. **Fees**: `Settlement.fees` now actually moves credits — deducted from the same escrow on top of `escrow_released` (checked against what was locked, like any other over-release), credited to a new local mock account, `EventLog.PLATFORM_DID`, standing in for a real platform/Insurer recipient (same trust boundary as the mocked bank/panel DIDs in conformance fixtures). CLI: `asp market contract --parent-contract <id>`, `asp market settle --fees <n>`. The other two items raised that day — appeals (to slash a juror's own stake) and the runtime→protocol compliance bridge — were deliberately deferred, each scoped as its own future slice rather than decided in passing. |
| S19 | Runtime → protocol compliance bridge: Action record (new, 2026-09-28) | An 18th record type, Action (`spec/schemas/action.schema.json`): self-issued, `{contract, scopes_used, summary?, artifacts?}`. It references a job's Contract by id without joining its own lifecycle chain — no lifecycle change, unlike S17. `EventLog.checkAction` requires the issuer to be that Contract's performer, the job to currently be Running or Checkpoint, and every `scopes_used` entry to already be granted by the Contract's live Mandate (tracked per-contract in a new `MandateRow`, projected from `mandate`, same pattern as `EscrowRow`); anything not granted is refused (`scope_violation`), and an unknown issuer, contract, or job state is refused outright. `artifacts` (optional, reusing the existing `artifactRef` common def) carries a hash of what a tool call's input actually was — data-flow fingerprinting — never the content itself, so a later dispute can prove what moved without the log ever holding it. Emission is real for one runtime as a proof-of-concept: `asp run --contract <id>` pipes the child process's live stdout and, for Claude Code, parses its existing `--output-format stream-json` tool_use blocks in real time via `LaunchPlan.checkOutputForAction`, mapping each call to a scope (`deriveScopeForTool`, shared with the existing pack-time `deriveScopes`) and a `sha256` fingerprint of its input. `deriveScopeForTool` also gained a `shell.network` split for `Bash`/`PowerShell` commands that look network-bound (`curl`, `wget`, `nc`, `ssh`, `scp`, a bare URL), narrowing what a blanket `shell.exec` grant quietly permits. CLI: `asp market action --contract <id> --by <did> --scopes-used <s> [--artifact <uri>=<sha256>]`. Honest limit, unchanged from the design discussion: self-reported, so a genuinely adversarial agent can simply not emit a violating action — this catches accidental scope creep and creates a real paper trail, not adversarial-proof monitoring. Codex/OpenHands emission and OS-level egress monitoring for fully-obfuscated indirect network calls are logged as backlog, not built (`docs/backlog.md`). |
| S20 | Kill switch: a real-time consequence for a caught violation (new, 2026-09-28) | No new record type or lifecycle change — reuses S19's live Mandate check and the existing `basis: "revoked"` Settlement. Before spawning the runtime, `asp run --contract <id>` fetches the contract's live Mandate once (`EventLog.mandateOf`); as `checkOutputForAction` detects each tool call in real time, the first scope outside that Mandate stops the child process (SIGTERM, then SIGKILL after a 3s grace period) instead of only being flagged once the run finishes. This can't undo the call that already happened — output is only ever seen after a tool call fires — but it stops every call after it, closing part of the "no live circuit-breaker" gap (`docs/backlog.md`). The economic consequence fires in the same motion: a `basis: "revoked"` Settlement, issued by the contract's own `bank` and cosigned by its `principal`, with `escrow_released: 0` and `bond_slashed` set to the full bond locked — the same split a Courts ruling of full fault would produce, without waiting for a human to notice the job stalled `Running` and open a dispute. Requires the bank's and principal's keys to be available locally to sign/cosign; without one, the kill still fires but the settlement is skipped with a logged note (an honest limit, same as the existing slash-lineage write in S15). Claude Code only, matching S19's own scoping. |
| S21 | Open-weight models on existing runtimes (new, 2026-10-04) | No record or lifecycle change. `asp run`/`orchestrate` take `--endpoint <url>` and `--api-key-env <NAME>` alongside `--model`; the OpenHands adapter sets `LLM_BASE_URL`/`LLM_API_KEY` and the Codex adapter generates an `asp_open` chat-completions provider override, so the same package runs on an open-weight model served from any OpenAI-compatible endpoint. The compliance bridge (S19) and kill switch (S20) extend to OpenHands via a `checkOutputForAction` that parses its headless ActionEvents. The parser follows the SDK's documented event shape and is tested against a fake only (`docs/backlog.md`). |
| S22 | Pre-call Mandate hook: prevention, not just reaction (new, 2026-10) | No record or lifecycle change; builds on S19 and S20. Under `asp run --contract <id>` on Claude Code, the contract's live Mandate scopes are snapshotted at run start and a `PreToolUse` hook blocks (exit 2) any call whose scope, mapped exactly as the compliance bridge maps it, is not granted, before the call runs. The hook fails closed on any error, makes no network calls, and records each block locally (`blocked-calls.ndjson`, reported by `asp run`). The kill switch (S20) still fires on the attempted call and settles as before; the hook guarantees the call itself never executes, which removes S20's limit that it could only stop the next call. Verified on real Claude Code 2.1.268; OpenHands and Codex are not covered yet (`docs/backlog.md`). |
| S23 | Strikes: a blocked attempt is recorded, not slashed (new, 2026-10) | Extends S22. The Action record (S19) gains an optional `blocked_attempts` array of `{scope, count}`: calls the runtime stopped before they ran because their scope wasn't in the Mandate. They are a signed strike, kept apart from `scopes_used` (which holds only what actually ran) and not checked against the Mandate by `checkAction`; a scope outside the Mandate in `scopes_used` is still refused. Policy in `asp run --contract` where the adapter blocks calls before they run: a blocked attempt does no harm, so it is recorded, not settled; a call that actually ran out of scope (the hook missing, failing open or timing out) stops the run with the full-fault settlement (S20); `--max-strikes N` (default 3) blocked attempts in one run read as probing and stop it the same way. `TodoWrite` and `ExitPlanMode` need no scope. Conformance vectors added: `valid_action_with_blocked_attempts`, `action_blocked_attempt_zero_count`, `action_blocked_attempt_missing_count`. Not yet: strikes do not raise the risk floor (`docs/backlog.md`). |
| S24 | Outcome verification and evidence grades (new, 2026-10) | No new record type and no lifecycle change. `Delivery.result.claims` (optional) lists each claim with a declared evidence grade (`measured`, `simulated`, `predicted`, new common def `evidenceGrade`) and an optional evidence reference. `Contract` and `Intent.verification` gain an optional `verifier` DID. `Attestation` gains kind `verification` (a standalone record about a Delivery, like `allocation`) with verdict `confirmed`, `partly_confirmed` or `not_confirmed` and a per-claim `claims` list of `{index, grade}` where grade adds `unverified`. `EventLog.checkVerification` requires the issuer to be the contract's named verifier and not the principal, the performer, or anyone either sponsors; the job to be Delivered; one verification per Delivery; claim indices to exist and be unique; `confirmed` and `partly_confirmed` to grade every claim; and `confirmed` never to hide a downgrade. `checkVerifiedBeforeAcceptance` refuses an acceptance, and `checkVerifiedBeforeSilence` a silence settlement, for a contract that names a verifier unless the Delivery has a verification that is not `not_confirmed`; rejection is unaffected. A new `verifications` table (migration 008) projects the verdict per delivery. Eight conformance vectors added (schema count 56 to 64). CLI: `asp market intent|contract --verifier`, `asp market deliver --claim`, `asp market verify`. Delayed settlement with hold-back and clawback is a separate, later lifecycle change (`docs/backlog.md`). |
| S25 | Approval gates: the Mandate says which scopes need the principal's say-so (new, 2026-10) | The Checkpoint record, the principal's `checkpoint_resolution` and the job lifecycle's Running/Checkpoint states already existed; this wires them to a live run. `Mandate.irreversible` gains an optional `scopes` list (granted scopes the policy applies to): `checkpoint` holds a call for approval, `forbid` blocks it, `allow` ungates it. `EventLog.checkMandateGates` refuses a Mandate that gates a scope it does not grant (`gate_not_granted`). In `asp run --contract` on Claude Code, the pre-call hook holds a gated call and asks `asp run`, which raises a performer-signed Checkpoint (`before_irreversible`, with the tool, scope and a 300-character summary) and waits for the principal's signed resolution: `approved` runs the call; `corrected` (with the reason), `picked`, or no answer within `--approval-wait` seconds (default 600) refuses it. A refusal is not a strike or a slash; the Checkpoint stays open after a timeout. CLI: `asp market mandate --gate`, `asp market checkpoint`, `asp market resolve`. Three conformance vectors added (schema count 64 to 67). The summary in the Checkpoint's `proposed_action` is masked for secret-looking text (`redactSecrets`) and cut to 300 characters before it reaches the log or the terminal. Known limits: masking is pattern-based, so an unusual secret shape could get through; only Claude Code holds calls; the log does not itself require an approved Checkpoint before an irreversible Action (`docs/backlog.md`). |
| S26 | A call counts as having run only if the runtime says it did (new, 2026-10) | No record or lifecycle change; tightens S23 and S25. Before, an out-of-scope call whose result was not the hook's refusal was assumed to have run and settled with full fault, which misjudged a call that the runtime's own permissions refused (and an approved gated call refused afterwards). On Claude Code the Mandate hook script is also registered for `PostToolUse` and `PostToolUseFailure`, which fire only for a call that actually ran, and records each in `executed-calls.ndjson`; `asp run` judges an out-of-scope or gated call against that record, rechecked for 3 seconds. Ran (even if it failed): violation, full fault. Did not run: a strike (`strike ... refused by the runtime before it ran`), or for a gated call, not counted in `scopes_used`. Runtimes without such a record keep the old assumption (`LaunchPlan.executedCallsFile` unset). Limits: a record that is late or unwritable turns a real violation into a strike; the file lives in the run directory (`docs/backlog.md`). |
| S27 | Allocation panel check and passport-driven earnings_split (new, 2026-10) | The log rejects an `allocation` Attestation unless its issuer is in the cited Proposal's Call `panel` (`not_on_call_panel`; unknown Proposal/Call also rejected). The performer's passport `earnings_split.agent_permille` is snapshotted when the Bond is posted (escrows gains `agent_permille`, sql/009) and applied at Settlement: the performer keeps that share of `escrow_released`, the rest goes to its passport sponsor (`earnings_split_no_sponsor` if none). `Settlement.earnings_split` is optional and may only restate the snapshot (`earnings_split_mismatch`), so the bank cannot choose the split. CLI: `asp market settle --agent-permille <n>` (assertion only). |
| S28 | Strikes nudge the risk floor, and decay (new, 2026-10) | No schema change. Blocked attempts in an agent's Action records (S23) are kept as dated entries on its reputation row (`strike_log`, sql/010). At Bond time the risk floor gains 10‰ per strike from the last 30 days (counted back from the Bond's own `issued_at`, so replay is deterministic), the performer's plus, if different, the backer's, capped at 200‰, on top of the slash terms. Strikes never demote or slash and age out after 30 days. `reputationOf` returns `{tier, slashCount, strikes}` (strikes held, entries older than 30 days before the latest strike are dropped). Only agents are tracked. |
| S29 | Graduated tier limits (new, 2026-10) | No schema change. A Mandate's `spend.cap` and `spend.per_action_max` may not exceed what the performer's tier allows: tier 1 at most 100 credits, tier 2 at most 1000, tier 3 and above uncapped (tier 0 stays excluded, `tier_excluded`). Over the limit fails with `tier_limit_exceeded`. Humans and untracked DIDs have no limit. `nodes.max_parallel` is limited too: tier 1 at most 4, tier 2 at most 16, tier 3 and above unlimited (same `tier_limit_exceeded`). Limits are constants (`TIER_SPEND_LIMIT`, `TIER_PARALLEL_LIMIT` in log.ts), not yet configurable. |
| S30 | Compliance bridge on Codex (new, 2026-10) | No protocol change. `asp run --backend codex --contract <id>` parses `codex exec --json` events (command_execution, file_change, mcp_tool_call, web_search) and reports real scopes in the Action record. Shell commands are classified: inspection-only commands (cat, Get-Content, rg, git status/diff/log, ...) are `repo.read`; commands that change files (redirects, Set-Content, rm, ...) are `repo.write`; push/PR/test/network keep their scopes; anything else is `shell.exec`. Detection and stop only: no pre-call hook, so an out-of-scope call stops the run with the full-fault settlement and there are no strikes or approval gates. |
