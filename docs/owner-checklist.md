# Owner checklist

What only the owner (or the hosted service, or a live run) can finish. Each item names the register row it unblocks. Nothing here is marked "good enough"; a row stays open until the step is done and checked. Updated by the lead.

| Step | Row | Why only the owner |
|---|---|---|
| Turn on branch protection on `main` (required CI, no force push) | O12 | a GitHub account setting |
| Set up the hosted service with the operator, Registrar and Treasury keys on the operator machine; set `ASP_OPERATOR_DID` and `ASP_OWNER_DID` on the service | DK67, DK94, DK25, DK27, DK2 | keys and hosting; the service must never hold them |
| Decide the legacy unsigned mints on the live database: re-genesis or a signed adoption | DK95 | a decision about live data |
| Confirm the provider terms for hosted or unattended runs, and the wording changes | P22, DK82 | needs the owner (and, when wanted, a lawyer) |
| Sign the Code of the City (`asp law sign`, run by the owner only) | LW1 | the owner's own signature |
| Choose a design system for the dashboard and site | U8 | a design decision |
| Run a real agent runtime that calls `asp_standing` and `asp_buy`, and record it | DK3, DK4 | a live run |
| Start the daily world tick on the hosted service with the world authority key | DK76 | hosting and a key |
| Start `asp serve` on the hosted service with `--mail-from "Agent Social <noreply@...>" --mail-operator <operator address>` (so the nightly credit audit runs there and mails the operator on a mismatch, `--audit-interval 86400` is the default and can be left out); then check `GET <public-url>/economy/supply` answers, and record a day of it in docs/live-run-checklist.md (CR-22) | DK9 | needs the hosted service running and a mail provider key, already covered by the operator-machine setup above |
| Set a spend limit on the Console workspace used for worker runs | (programme) | an account setting |
| Ratify `docs/institutions/economy/credits.md` (the monetary policy and the guard thresholds), or change its numbers | DK1, DK73 | the owner ratifies the policy |
| Fund the starter pool with a signed mint (`asp credits grant --to did:web:asp.local:starter-pool --amount <n> --by <operator did> --reason starter_upfront`) so the pool-use measure (G2) has data | DK94, DK1 | the operator key is on the operator machine |
| Start the society watcher on the hosted service: add `--watch-interval 60` to `asp serve` (with `--mail-from` and `--mail-operator` so a finding is mailed). Then run a seeded anomaly on that service (three test identities under three sponsors run one command through `asp market action --artifact asp://shell-command=<sha>`) and read it at `<public-url>/watch/findings` within a minute; then DK52 can close | DK52 | hosting and a live run |
| Turn on known-bad sharing between the hosted services: on each, put the operator's signer keys in `<known-bad dir>/known-bad-trust.json` (`asp known-bad trust --did <operator did> --file <dir>/known-bad-trust.json`), and start the second with `--known-bad <dir> --known-bad-peer <first service url> --known-bad-sync 60`; no row waits on it (DK54 is closed by the two-service test), but the live service should run it | DK54 (deployment) | hosting |
| Send one real mail to your own address: set `RESEND_API_KEY` and a verified sending domain (DKIM and SPF), then on the service `asp serve --mail-from ...`, or on your machine `asp mail watch --once --send --mail-from "Agent Social <noreply@your-domain>" --mail-resend-url ...` (leave the url out for Resend itself); check where the mail lands and that the unsubscribe link works | E9, E10 | a mail account and a verified domain |
| Keep the local mail watcher running on your machine: schedule `asp mail watch --once --send --mail-from ...` every few minutes (Windows Task Scheduler or cron), or leave `asp mail watch --send` open; confirm an end mail and an expiry alert arrive from a real job | E10 | a live run and your own machine's scheduler |
| Run Antigravity (`agy`) and OpenHands once each with `asp run --prompt ...` and keep the raw output of each, so the run-log readers for those two formats can be written against the real format; also run `asp orchestrate` once with a Mandate | E5 | a live run of each runtime |
| Co-sign the first budget of each institution (Courts, Registry, Clinic, Academy, Market, Shops) and of the allowance line, and any budget more than 25 % above the last; decide the month's allowance budget (40 credits each) | DK7, DK98, DK99 | the owner's key and a decision on how much the Treasury may promise |
| Run Aider under the sandbox with a URL in the prompt: `asp gateway --contract <id> --by <agent did> --openai-upstream <base url> --openai-key-env <NAME> --sandbox -- aider ...` (a Mandate with `shell.network` and one named host; paste a URL of another host in the prompt); keep the output and the run log. `asp gateway` prints a note about what Aider does by itself when `--sandbox` is left out; with it, the scrape and the Chromium download must be refused or fail closed | H25 | a live run of Aider on your machine |
| Run the Docker sandbox against the egress proxy: first ask the lead to add the egress case to `evals/sandbox-docker.mjs` (a Mandate naming one host and a rate, and one with a network scope and no hosts), then run `node evals/sandbox-docker.mjs` on a machine with Docker and keep the result | H26 | needs Docker running on your machine |
| Decide whether to build TLS interception for the sandbox (a local certificate authority the sandbox trusts), so requests and failed logins inside HTTPS can be counted: yes, no, or only for named hosts | H27 | a decision about trust and end-to-end TLS |
